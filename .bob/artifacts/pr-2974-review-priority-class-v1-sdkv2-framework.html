🟡 Suggestions (Non-Blocking)

S1 — Update() sends unconditional AddOperation for description and globalDefault
File: priority_class_v1_crud.go:177–184

The SDKv2 Update uses if d.HasChange(...) before appending patch ops. The Framework Update always appends AddOperation for both fields even when unchanged.

// Always appended, even when unchanged:
ops = append(ops, &kubernetes.AddOperation{Path: "/description",   Value: plan.Description.ValueString()})
ops = append(ops, &kubernetes.AddOperation{Path: "/globalDefault", Value: plan.GlobalDefault.ValueBool()})

Impact: Not breaking. The Kubernetes API accepts an idempotent add with the same value and returns the same state. Only consequence is a slightly larger patch payload on updates. No user-visible drift.

S2 — Update() does not reflect preemption_policy from API response
File: priority_class_v1_crud.go:216–218

After the JSON PATCH, Update() sets PreemptionPolicy only if out.PreemptionPolicy != nil. Since preemption_policy is RequiresReplace, this path is only hit when the field is unchanged — the value in the plan will always match. Not a correctness issue in practice, but subtly inconsistent with the Read path.

S3 — No CheckDestroy in the new acceptance tests
File: priority_class_v1_test.go

The removed SDKv2 test suite had CheckDestroy: testAccCheckKubernetesPriorityClassV1Destroy on every case, which verified via the Kubernetes API that the object was actually deleted. The new Framework tests rely on the test framework's own cleanup but do not make this API assertion. The TestAccPriorityClassV1_disappears test covers the deletion code path functionally.

S4 — diffMetadataPatch helper is defined but never called
File: priority_class_v1_helpers.go:87–100

diffMetadataPatch builds a patch for annotation/label diffs but Update() inlines the equivalent logic directly. This is dead code and should be removed to avoid confusion.

S5 — metadata.0.generation unnecessarily excluded from ImportStateVerifyIgnore
File: priority_class_v1_test.go:50–53

The new import test ignores both metadata.0.resource_version and metadata.0.generation. The SDKv2 test only ignored resource_version. Since generation is a Computed:true field that is populated on every Read (including ImportState), it could be asserted. Low impact.
