```release-note:breaking-change
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`: Migrate to the Terraform Plugin Framework. Container and init container `resources`, Deployment and DaemonSet `strategy` and its `rolling_update`, and StatefulSet `persistent_volume_claim_retention_policy` change from blocks to object arguments, for example `resources = { ... }`. Pod spec `image_pull_secrets` and `readiness_gate` become lists of objects. See the v4 upgrade guide.
```

```release-note:breaking-change
`resource/kubernetes_pod_v1`: Migrate to the Terraform Plugin Framework. Container and init container `resources` change from blocks to object arguments, for example `resources = { ... }`. `image_pull_secrets` and `readiness_gate` become lists of objects. See the v4 upgrade guide.
```

```release-note:breaking-change
`resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Migrate to the Terraform Plugin Framework. JobSpec `selector` and container and init container `resources` change from blocks to object arguments, for example `selector = { ... }`. `selector.match_expressions`, pod spec `image_pull_secrets` and `readiness_gate` become lists of objects. See the v4 upgrade guide.
```

```release-note:breaking-change
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: State upgrades convert the selected singleton lists to objects. Remove the corresponding `[0]` from references and `ignore_changes` child paths, and update module interfaces that expose these values from `list(object(...))` to `object(...)`. Omit an object or use `null` to leave it unset; use `{}` for an explicit empty object. Existing 3.x versioned resources do not need a `moved` block or re-import.
```

```release-note:breaking-change
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: The state schema version increases. Once this version has written the state, provider 3.x cannot read it, so back up state before upgrading.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Resource type names, `namespace/name` import IDs, import identities and existing state are kept, and an unchanged configuration normally plans no change. Values that earlier versions stored differently, such as explicitly empty `labels = {}`, can show a one-time in-place update that changes only Terraform state. With Terraform 1.8 or later, `moved` blocks can move resources from the deprecated `kubernetes_deployment`, `kubernetes_daemonset`, `kubernetes_stateful_set`, `kubernetes_pod`, `kubernetes_job` and `kubernetes_cron_job` types.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: A pod `security_context` block that sets only empty values, such as `supplemental_groups = []`, no longer plans a change on every run; as in earlier versions, it is sent as an empty security context, and an explicit `run_as_non_root = false` is sent as `runAsNonRoot: false`.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: After a create or update, state records the planned values, and only values the plan leaves unknown come from Kubernetes. Fields that admission webhooks or other clients add, such as an injected sidecar container, show as drift on the next refreshed plan instead of being recorded by the apply; `lifecycle.ignore_changes` handles them as before.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_cron_job_v1`: Updates change only what the plan changes instead of replacing the whole spec (Deployment, DaemonSet, CronJob) or the whole pod template (StatefulSet). Spec fields that the configuration does not manage keep their live values. A change made outside Terraform to a managed field after the plan, such as with `-refresh=false` or a saved plan, is kept by that apply when the plan does not change that field, and reverted by the next refreshed apply.
```

```release-note:note
`resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`: A plan that changes a Pod spec or a Job pod template reads the object from Kubernetes, even with `-refresh=false`, to decide whether it must be replaced. Planning fails if that read fails or takes longer than 30 seconds.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Setting both `name` and `generate_name` in `metadata` gives a warning, since Kubernetes ignores `generate_name` when `name` is set.
```

```release-note:note
`resource/kubernetes_pod_v1`: New Pods keep resource quantities as configured in state, for example `0.5` rather than `500m`, which can change outputs but not allocations.
```

```release-note:note
`resource/kubernetes_stateful_set_v1`: As in earlier versions, a change to the `requests`, labels or annotations of a `volume_claim_template` is planned in place but not applied, because Kubernetes does not allow it. The plan now warns about it; replace the StatefulSet to apply such a change.
```

