Analysis
id Optional+Computed (SDKv2) → Computed-only (Framework) — not a release blocker

SDKv2 injects id as Optional: true, Computed: true into every *schema.Resource via core_schema.go:315-320, including data sources. The Framework implementation declares id as StringAttribute{Computed: true} (read-only).

The Framework's attribute_validation.go:127-133 would fire "Invalid Configuration for Read-Only Attribute" if a user set id = "…" in their data source block. However:

  • This pattern is not documented anywhere in this provider's docs, examples, or Registry page.
  • No testconfig, README, or HCL example in this repository sets id = on this data source.
  • The SDKv2 Read unconditionally overwrote any user-supplied id anyway — so any config that set it would have been silently non-functional under SDKv2 too.
  • The Computed: true declaration correctly expresses the intended semantics of this attribute.

Verdict: Not a release-blocking regression. The behavioral change is from "you can set this (but it is ignored)" to "you cannot set this (validation error)". No real-world user is affected.

🔴 Blocking Findings (static review)

None of these affect the data source's behavior or the release. They are structural quality issues that affect future migrations landing in the same package.

P1
B1 — Framework-only factory in corev1_test.go will break future Core v1 migrations
corev1_test.go:31K8S-MIGRATE-019
Trigger
testAccProtoV6ProviderFactories uses providerserver.NewProtocol6WithError(provider.New(...)) — a Framework-only server. The factory is package-owned and inherited by every future PR in corev1.
Failure
K8S-MIGRATE-019 measured a 6/15 failure rate from this pattern. The moment any test in package corev1_test uses an SDKv2-served resource as a fixture (e.g. kubernetes_config_map_v1, kubernetes_namespace_v1), it fails with Invalid resource type — The provider hashicorp/kubernetes does not support resource type.
Impact
The corev1 package is named for Kubernetes Core API v1, which contains dozens of SDKv2 data sources. The next migration PR that uses one as a fixture inherits this bug.
Correction
Replace the factory with a mux factory that reconstructs all three servers inline (matching internal/mux/mux.go).
var testAccProtoV6ProviderFactories = map[string]func() (tfprotov6.ProviderServer, error){
    "kubernetes": func() (tfprotov6.ProviderServer, error) {
        ctx := context.Background()
        kubernetesProvider := kubernetes.Provider()
        kubernetesProvider.Configure(ctx, sdkv2.NewResourceConfigRaw(nil))
        upgradedSdk, err := tf5to6server.UpgradeServer(ctx, kubernetesProvider.GRPCProvider)
        if err != nil { return nil, err }
        upgradedManifest, err := tf5to6server.UpgradeServer(ctx, manifestprovider.Provider())
        if err != nil { return nil, err }
        return tf6muxserver.NewMuxServer(ctx,
            func() tfprotov6.ProviderServer { return upgradedSdk },
            func() tfprotov6.ProviderServer { return upgradedManifest },
            providerserver.NewProtocol6(provider.New("test", kubernetesProvider.Meta)),
        )
    },
}
