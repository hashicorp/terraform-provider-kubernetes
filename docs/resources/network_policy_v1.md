# kubernetes_network_policy_v1

Kubernetes supports network policies to specify how groups of pods are allowed to communicate with each other and with other network endpoints. NetworkPolicy resources use labels to select pods and define rules which specify what traffic is allowed to the selected pods. Read more about network policies at https://kubernetes.io/docs/concepts/services-networking/network-policies/

### Nested Schema for `spec`

Required:

- `pod_selector` (Attributes) podSelector selects the pods to which this NetworkPolicy object applies. The array of ingress rules is applied to any pods selected by this field. Multiple network policies can select the same set of pods. In this case, the ingress rules for each are combined additively. This field is NOT optional and follows standard label selector semantics. An empty podSelector matches all pods in this namespace. (see [below for nested schema](#nestedatt--spec--pod_selector))
- `policy_types` (List of String) policyTypes is a list of rule types that the NetworkPolicy relates to. Valid options are ["Ingress"], ["Egress"], or ["Ingress", "Egress"]. If this field is not specified, it will default based on the existence of ingress or egress rules; policies that contain an egress section are assumed to affect egress, and all policies (whether or not they contain an ingress section) are assumed to affect ingress. If you want to write an egress-only policy, you must explicitly specify policyTypes [ "Egress" ]. Likewise, if you want to write a policy that specifies that no egress is allowed, you must specify a policyTypes value that include "Egress" (since such a policy would not include an egress section and would otherwise default to just [ "Ingress" ]). This field is beta-level in 1.8

Optional:

- `egress` (Block List) egress is a list of egress rules to be applied to the selected pods. Outgoing traffic is allowed if there are no NetworkPolicies selecting the pod (and cluster policy otherwise allows the traffic), OR if the traffic matches at least one egress rule across all of the NetworkPolicy objects whose podSelector matches the pod. If this field is empty then this NetworkPolicy limits all outgoing traffic (and serves solely to ensure that the pods it selects are isolated by default). This field is beta-level in 1.8 (see [below for nested schema](#nestedblock--spec--egress))
- `ingress` (Block List) ingress is a list of ingress rules to be applied to the selected pods. Traffic is allowed to a pod if there are no NetworkPolicies selecting the pod (and cluster policy otherwise allows the traffic), OR if the traffic source is the pod's local node, OR if the traffic matches at least one ingress rule across all of the NetworkPolicy objects whose podSelector matches the pod. If this field is empty then this NetworkPolicy does not allow any traffic (and serves solely to ensure that the pods it selects are isolated by default) (see [below for nested schema](#nestedblock--spec--ingress))

## Example Usage

```terraform
resource "kubernetes_network_policy_v1" "example" {
  metadata {
    name      = "terraform-example-network-policy"
    namespace = "default"
  }

  spec {

    ingress {
      ports {
        port     = "http"
        protocol = "TCP"
      }
      ports {
        port     = "8125"
        protocol = "UDP"
      }

      from {
        namespace_selector = {
          match_labels = {
            name = "default"
          }
        }
      }

      from {
        ip_block = {
          cidr = "10.0.0.0/8"
          except = [
            "10.0.0.0/24",
            "10.0.1.0/24",
          ]
        }
      }
    }

    egress {} # single empty rule to allow all egress traffic

    policy_types = ["Ingress", "Egress"]
    pod_selector = {
      match_expressions = [{
        key      = "name"
        operator = "In"
        values   = ["webfront", "api"]
      }]
    }
  }
}
```

## Migration to Plugin Framework

`kubernetes_network_policy_v1` is implemented using the Terraform Plugin Framework. Apply the object syntax changes below before upgrading. The resource type and Kubernetes object identity are retained.

### Object configuration and state upgrade

The resource now uses state schema version 1 and upgrades existing version 0
state automatically. Identity schema version 1 is unchanged. Existing
`kubernetes_network_policy_v1` resources need no `moved` block or re-import.

Keep `metadata`, `spec`, `ingress`, `egress`, `from`, `to`, and `ports` as blocks.
Change these fields from singleton blocks to object arguments:

- Required `spec[0].pod_selector`.
- `spec[0].ingress[*].from[*].ip_block`, `namespace_selector`, and `pod_selector`.
- `spec[0].egress[*].to[*].ip_block`, `namespace_selector`, and `pod_selector`.

Every selector's repeated `match_expressions` blocks become a list of objects.
For example, replace `pod_selector { match_expressions { ... } }` with:

```terraform
pod_selector = {
  match_expressions = [{
    key      = "app"
    operator = "In"
    values   = ["frontend", "api"]
  }]
}
```

Preserve empty selectors deliberately: `pod_selector = {}` at the root selects
all pods in the policy's namespace. An omitted or null peer `namespace_selector`
is absent; `namespace_selector = {}` is present and selects all namespaces.
Changing omission into `{}` can broaden access. Keep absent optional selectors
and IP blocks omitted or null; retain present empty selectors as `{}`.

Remove indexes only for the converted objects in references and lifecycle paths.
For example, `spec[0].ingress[0].from[0].namespace_selector[0].match_labels`
becomes `spec[0].ingress[0].from[0].namespace_selector.match_labels`.
Use the new path in `ignore_changes` too. The `spec`, ingress/egress rule, peer,
and `match_expressions` lists retain their indexes.

Replace dynamic optional selector blocks with object expressions, preserving
whether the selector was absent. An optional module input can be declared as:

```terraform
variable "peer_namespace_selector" {
  type = object({
    match_labels = optional(map(string))
    match_expressions = optional(list(object({
      key      = string
      operator = string
      values   = optional(set(string))
    })))
  })
  default = null
}

# Inside a from or to block:
# namespace_selector = var.peer_namespace_selector
# Or: namespace_selector = var.all_namespaces ? {} : null
```

Terraform JSON uses objects such as `"pod_selector": {"match_labels":
{"app": "frontend"}}` and `"namespace_selector": {}`. Expression lists stay
arrays: `"match_expressions": [{"key": "app", "operator": "Exists"}]`.
The converter rejects multiple historical elements in each singleton selector
or IP block and preserves every actual rule, peer, port, and expression.

Before upgrading, confirm that the current configuration has an empty plan. Review the plan after upgrading; do not apply unexpected replacement or specification changes.

The first upgrade can normalize these empty values in Terraform state:

- `metadata.labels = {}` and `metadata.annotations = {}` can change from `null` to `{}`.
- `match_labels = {}` can change from `null` to `{}` at these selector paths:
  - `spec.pod_selector`
  - `spec.ingress[*].from[*].namespace_selector`
  - `spec.ingress[*].from[*].pod_selector`
  - `spec.egress[*].to[*].namespace_selector`
  - `spec.egress[*].to[*].pod_selector`
- At each selector path above, `match_expressions[*].values = []` can change from `null` to `[]` only for the `Exists` and `DoesNotExist` operators.
- An omitted `match_expressions` argument can change from the old empty block list `[]` to `null`.

These changes can appear as a one-time in-place update. Applying them updates Terraform state, preserves the policy and its UID, and leaves the next plan empty.

After create or update, state retains known planned specification values. Changes made by admission webhooks appear as drift on the next refresh.

### Migration from `kubernetes_network_policy`

The deprecated alias remains on SDKv2. With Terraform 1.8 or later, replace the old resource block's type with `kubernetes_network_policy_v1`, apply the object syntax changes above while keeping the same settings, update references, and add:

```terraform
moved {
  from = kubernetes_network_policy.example
  to   = kubernetes_network_policy_v1.example
}
```

Do not keep both resource declarations for the same Kubernetes object.

### Resource identity

With Terraform 1.12 or later, resource identity contains `api_version` (`networking.k8s.io/v1`), `kind` (`NetworkPolicy`), `name`, and `namespace`. The existing namespace/name import identifier is unchanged.

## Import

Network policies can be imported using their identifier consisting of `<namespace-name>/<network-policy-name>`, e.g.:

```
$ terraform import kubernetes_network_policy_v1.example default/terraform-example-network-policy
```
