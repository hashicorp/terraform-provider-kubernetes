```release-note:breaking-change
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`: Migrate to the Terraform Plugin Framework. Container and init container `resources`, pod spec `image_pull_secrets` and `readiness_gate`, Deployment and DaemonSet `strategy` and its `rolling_update`, and StatefulSet `persistent_volume_claim_retention_policy` change from blocks to list-of-object arguments, for example `resources = [{ ... }]`. An empty list is rejected; omit the argument instead. See the v4 upgrade guide.
```

```release-note:breaking-change
`resource/kubernetes_pod_v1`: Migrate to the Terraform Plugin Framework. Container and init container `resources`, `image_pull_secrets` and `readiness_gate` change from blocks to list-of-object arguments, for example `resources = [{ ... }]`. An empty list is rejected; omit the argument instead. See the v4 upgrade guide.
```

```release-note:breaking-change
`resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Migrate to the Terraform Plugin Framework. The Job `selector` and its `match_expressions`, container and init container `resources`, and pod spec `image_pull_secrets` and `readiness_gate` change from blocks to list-of-object arguments, for example `selector = [{ ... }]`. An empty list is rejected; omit the argument instead. See the v4 upgrade guide.
```

```release-note:breaking-change
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: The state schema version increases. Once this version has written the state, provider 3.x cannot read it, so back up state before upgrading.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Resource type names, `namespace/name` import IDs, import identities and existing state are kept, and an unchanged configuration normally plans no change. Values that earlier versions stored differently, such as explicitly empty `labels = {}`, can show a one-time in-place update that changes only Terraform state. With Terraform 1.8 or later, `moved` blocks can move resources from the deprecated `kubernetes_deployment`, `kubernetes_daemonset`, `kubernetes_stateful_set`, `kubernetes_pod`, `kubernetes_job` and `kubernetes_cron_job` types.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: A pod `security_context` block that sets only empty values, such as `supplemental_groups = []`, no longer plans a change on every run; as in earlier versions, it is sent as an empty security context, and an explicit `run_as_non_root = false` is sent as `runAsNonRoot: false`.
```

```release-note:note
`resource/kubernetes_pod_v1`: New Pods keep resource quantities as configured in state, for example `0.5` rather than `500m`, which can change outputs but not allocations.
```

```release-note:note
`resource/kubernetes_stateful_set_v1`: As in earlier versions, a change to the `requests`, labels or annotations of a `volume_claim_template` is planned in place but not applied, because Kubernetes does not allow it. The plan now warns about it; replace the StatefulSet to apply such a change.
```

```release-note:bug
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Keep the configured spelling of a number Kubernetes stores, such as `run_as_user = "01000"` or `replicas = "01"`, instead of planning a change, or replacing a Pod or Job, on every plan.
```

```release-note:bug
`resource/kubernetes_pod_v1`: Replace the Pod when a spec field that Kubernetes cannot update changes, such as a volume, volume mount, probe or affinity, or when `active_deadline_seconds` is raised or removed. Earlier versions reported success without changing the Pod, or failed to apply.
```

```release-note:bug
`resource/kubernetes_pod_v1`: Record the priority class Kubernetes assigns to a Pod that leaves out `priority_class_name`, such as a `globalDefault` PriorityClass, instead of replacing the Pod on every plan.
```

```release-note:bug
`resource/kubernetes_pod_v1`: Keep a configured toleration of a built-in taint, such as `node.kubernetes.io/not-ready` with `toleration_seconds`, instead of replacing the Pod on every plan.
```

```release-note:bug
`resource/kubernetes_pod_v1`: Keep several projections in one `projected` volume `sources` block without reporting a change on every plan.
```

```release-note:bug
`resource/kubernetes_job_v1`: Apply changes to `ttl_seconds_after_finished` and `max_failed_indexes` to the Job.
```

```release-note:bug
`resource/kubernetes_job_v1`: Replace the Job when its pod template or `pod_failure_policy` changes, since Kubernetes does not allow updating them. Labels the Job controller adds to the pod template are ignored, and pod template labels and annotations an admission webhook adds are not recorded in state.
```

```release-note:bug
`resource/kubernetes_cron_job_v1`: Keep labels, annotations and spec fields that are not recorded in state, such as those set by admission controllers or other tools, when updating a CronJob.
```
