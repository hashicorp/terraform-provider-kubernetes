P0 · TEST GATE Finding 3 — Migration test version constraint not pinned to an exact release K8S-MIGRATE-017

The migration test in data_source_config_map_v1_migration_test.go:31 uses VersionConstraint: "~> 2.0". K8S-MIGRATE-017 requires one exact pinned version (e.g. "= 3.2.1"). Using a range makes the test non-deterministic: a future 2.x release with different behavior silently changes the baseline. The previous release series in this repo is 3.x, so ~> 2.0 also tests against an older major series than what existing users have deployed.

Current (non-deterministic)
ExternalProviders: map[string]resource.ExternalProvider{
    "kubernetes": {
        Source:            "hashicorp/kubernetes",
        VersionConstraint: "~> 2.0",  // resolves to latest 2.x — non-deterministic
    },
},
Recommended fix: Change to "= 3.2.1" (the last published release). This is the exact version existing users are upgrading from.
P0 · TEST GATE Finding 4 — Migration test does not assert an empty plan after Framework upgrade K8S-MIGRATE-015

Step 2 of the migration test sets ExpectNonEmptyPlan: false. This is the default value of the field — it does not cause the test to fail if the plan is non-empty. It is semantically a no-op. The test framework only fails on a non-empty plan when PlanOnly: true is set together with ExpectNonEmptyPlan: false, or through a dedicated refresh step.

As a result, Findings 1 and 2 produce output changes on the upgrade plan, yet the migration test passes silently because neither id nor namespace is asserted in the step 2 Check function — only metadata.0.name and data.one are checked.

    // id NOT checked

Recommended fix: Add a third step with PlanOnly: true and ExpectNonEmptyPlan: false to prove convergence after the Framework apply. Extend step 2 assertions to include metadata.0.namespace = "default" and verify id is set and non-empty.

🟡 Non-Blocking Suggestions

SUGGESTION S1 — Validators dropped for annotations, labels, name K8S-MIGRATE-003

SDKv2 schema inherits validateAnnotations, validateLabels, and validateName via namespacedMetadataSchema. The Framework schema has no plan-time validators on these fields. For a read-only data source the user impact is limited (the Kubernetes API will still reject invalid values), but users lose early plan-time feedback. Not a correctness regression, but a degradation of the DX contract.

SUGGESTION S2 — name changed from Optional+Computed to Required K8S-MIGRATE-004 / K8S-MIGRATE-007

SDKv2 metadataFields declares name as Optional + Computed + ForceNew. The PR declares it Required. In practice no legitimate data source config omits name, so no user is broken. However this is a silent schema contract change. It should either be documented as intentional or left as Optional + Computed to preserve exact parity.
