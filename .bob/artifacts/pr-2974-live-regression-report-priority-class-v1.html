🔴 Blocking Findings

BF-1 — P0 CRASH: Provider panics when metadata block is omitted
Severity: P0 / Release-blocking  |  File: priority_class_v1_crud.go:37

Root cause: listvalidator.SizeBetween(1,1) on a ListNestedBlock is evaluated at apply time, not plan time. A config with no metadata block passes planning and reaches Create(), where plan.Metadata[0] panics on an empty slice.

Crash trace (reproduced live):

panic: runtime error: index out of range [0] with length 0

goroutine 85 [running]:
schedulingv1.(*PriorityClassV1).Create(...)
    priority_class_v1_crud.go:37 +0x87c

HCL that triggers it:

resource "kubernetes_priority_class_v1" "no_meta" {
  value = 100   # no metadata block
}

SDKv2 behavior: metadata is Required: true, MaxItems: 1 — Terraform rejects the config at plan time with "Missing required argument". No crash.

Migrated behavior: Plan succeeds (exit 0). Apply panics the provider process.

Fix: Add a ConfigValidator (e.g. resource.ConfigValidatorsResponse with a custom validator) that checks len(config.Metadata) == 1 at plan time, OR change the metadata block to be represented as a SingleNestedBlock (which enforces presence). The simplest fix is a plan-time validator that fires before Create is reached.

BF-2 — Breaking regression: generate_name resources force replacement on any secondary change
Severity: Critical / Release-blocking  |  File: priority_class_v1_schema.go:58–68

Root cause: metadata.name is Optional+Computed with RequiresReplace() but no UseStateForUnknown(). When generate_name is used and name is not in the HCL config, Framework leaves name as unknown in the plan. RequiresReplace then fires because the attribute transitions from a known value (in state) to unknown (in plan).

Reproduction (live):

# Step 1 — create
resource "kubernetes_priority_class_v1" "test" {
  metadata { generate_name = "probe4-genname-" }
  value = 150
}
# Server assigns name = "probe4-genname-jmz2m"

# Step 2 — add a label (should be in-place update)
resource "kubernetes_priority_class_v1" "test" {
  metadata {
    generate_name = "probe4-genname-"
    labels = { team = "platform" }
  }
  value = 150
}
# terraform plan output:
~ metadata {
    ~ name = "probe4-genname-jmz2m" -> (known after apply)  # forces replacement
  }
Plan: 1 to add, 0 to change, 1 to destroy.

SDKv2 behavior: Adding a label to a generate_name resource is an in-place update. The name is preserved in state and does not appear in the diff.

Migrated behavior: Destroy-before-create. The existing PriorityClass is deleted and a new one (with a new random suffix) is created.

Impact: Any user who created a PriorityClass with generate_name and later adds labels or annotations will silently get a replacement instead of an update. The UID changes; any pods referencing the old PriorityClass by name (different suffix) will lose priority class association.

Fix: Add stringplanmodifier.UseStateForUnknown() to metadata.name alongside RequiresReplace(). This preserves the server-assigned name in the plan when it is not in config, preventing spurious replacements. The peer implementation (admissionregistrationv1) has neither modifier on name — for this resource, both are needed because name is immutable once set.

// Fix in priority_class_v1_schema.go
"name": schema.StringAttribute{
    Optional: true,
    Computed: true,
    PlanModifiers: []planmodifier.String{
        stringplanmodifier.UseStateForUnknown(),  // ADD THIS
        stringplanmodifier.RequiresReplace(),
    },
    ...
},
