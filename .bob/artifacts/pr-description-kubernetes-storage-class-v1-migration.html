## Summary

Migrates `kubernetes_storage_class_v1` from SDKv2 to the Terraform Plugin Framework
using the incremental mux-based approach. The resource is now served by the Framework
provider. The deprecated `kubernetes_storage_class` alias is retained in the SDKv2 map
to support `moved {}` block migrations from existing state.

## Changes

### New: `internal/framework/provider/storagev1/`

- Full Framework implementation: schema, model, CRUD, helpers, MoveState
- `MoveState` handler enabling:
  ```hcl
  moved {
    from = kubernetes_storage_class.x
    to   = kubernetes_storage_class_v1.x
  }
  ```
- 11 unit tests for MoveState (no cluster) + 10 acceptance tests including SDKv2 upgrade and moved block tests

### Modified

| `kubernetes/patch_operations.go`, `kubernetes/structures.go` | Exports `DiffStringMap`, `IsInternalKey`, `IgnoreKey` for use by Framework helpers |
| `kubernetes/resource_kubernetes_config_map_v1.go`, `kubernetes/patch_operations_test.go`, `kubernetes/structures_test.go` | Updated call sites for newly exported helpers |

## Design Notes

- **`ListNestedBlock`** used for all blocks — produces identical JSON state to SDKv2's
  `TypeList{MaxItems:1}`, so `schema_version` stays at `0` and no `UpgradeState` handler
  is needed
- **`SetAttribute`** used for `mount_options` — mirrors SDKv2's `TypeSet` semantics,
  preserving order-independent diff behaviour
- **`RequiresReplace`** on `storage_provisioner` and `volume_binding_mode` — mirrors
  SDKv2 `ForceNew`, since the Kubernetes API forbids patching these fields after creation
- **Null-preserving `mount_options`**: omitting `mount_options` in config keeps state
  null (not empty set), avoiding a perpetual `[delete create]` plan cycle
- **`3.0.1`** used as the source version in the `moved` acceptance test — `3.2.1` causes
  a routing conflict where both SDKv2 and Framework sides claim `kubernetes_storage_class_v1`,
  preventing `MoveState` from firing
