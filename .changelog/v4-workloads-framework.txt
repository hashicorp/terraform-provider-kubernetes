```release-note:breaking-change
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`: Migrate to the Terraform Plugin Framework. Container and init container `resources`, pod template `image_pull_secrets` and `readiness_gate`, Deployment and DaemonSet `strategy` (including `rolling_update`), and StatefulSet `persistent_volume_claim_retention_policy` now use list-of-object assignment syntax, for example `resources = [{ ... }]`. See the apps/v1 Plugin Framework migration guide.
```

```release-note:breaking-change
`resource/kubernetes_pod_v1`: Migrate to the Terraform Plugin Framework. Container and init container `resources`, `image_pull_secrets` and `readiness_gate` now use list-of-object assignment syntax, for example `resources = [{ ... }]`. See the Pod Plugin Framework migration guide.
```

```release-note:breaking-change
`resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Migrate to the Terraform Plugin Framework. The Job `selector` (including `match_expressions`), pod template `image_pull_secrets` and `readiness_gate`, and container and init container `resources` now use list-of-object assignment syntax, for example `selector = [{ ... }]`; an empty list is rejected, so omit them instead. The pod template is the same as in the apps/v1 workloads. See the Job and CronJob Plugin Framework migration guide.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Resource type names, `namespace/name` import IDs and existing state are kept, so no re-import or `moved` block is needed. With Terraform 1.8 or later, `moved` blocks can move resources from the deprecated `kubernetes_deployment`, `kubernetes_daemonset`, `kubernetes_stateful_set`, `kubernetes_pod`, `kubernetes_job` and `kubernetes_cron_job` types.
```

```release-note:note
`resource/kubernetes_deployment_v1`, `resource/kubernetes_daemon_set_v1`, `resource/kubernetes_stateful_set_v1`, `resource/kubernetes_pod_v1`, `resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: State written by earlier versions is upgraded so that unchanged metadata plans no update, also with `-refresh=false`. The state schema version increases, so once this version has written the state, earlier provider versions cannot read it.
```

```release-note:note
`resource/kubernetes_job_v1`, `resource/kubernetes_cron_job_v1`: Omitted optional values keep the empty or zero values earlier versions stored, so state written by them plans no change for an unchanged configuration. A one-time in-place update can still appear for explicitly empty values such as `labels = {}`; it changes only Terraform state.
```

```release-note:note
`resource/kubernetes_pod_v1`: New Pods keep resource quantities as configured in state (for example `0.5` rather than `500m`), which can change outputs but not allocations.
```

```release-note:bug
`resource/kubernetes_pod_v1`: Replace the Pod when a spec field that Kubernetes cannot update in place changes, such as a volume, volume mount, probe or affinity. Earlier versions reported success without changing the Pod and planned the same change again.
```

```release-note:bug
`resource/kubernetes_pod_v1`: Keep several projections in one `projected` volume `sources` block without reporting a change on every plan.
```

```release-note:bug
`resource/kubernetes_job_v1`: Apply changes to `ttl_seconds_after_finished` and `max_failed_indexes` to the Job.
```

```release-note:bug
`resource/kubernetes_job_v1`: Replace the Job when `pod_failure_policy` rules or its pod template change, since Kubernetes does not allow updating them. Labels the Job controller adds to the pod template are ignored.
```

```release-note:bug
`resource/kubernetes_cron_job_v1`: Keep labels, annotations, and spec fields that are not recorded in state, such as internal `kubernetes.io/` keys, keys matched by the provider `ignore_labels` and `ignore_annotations` settings, and fields set by admission controllers or other tools, when updating a CronJob.
```

```release-note:note
`resource/kubernetes_stateful_set_v1`: As in earlier versions, a change to the `requests`, labels or annotations of a `volume_claim_template` is planned in place but not applied, because Kubernetes does not allow it, and the next plan shows it again. The plan now warns about it; replace the StatefulSet to apply such a change.
```
