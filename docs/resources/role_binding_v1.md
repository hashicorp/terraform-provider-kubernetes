# kubernetes_role_binding_v1

A RoleBinding may be used to grant permissions defined in a Role to a set of subjects within a namespace.

Exactly one `metadata` block, exactly one `role_ref` block, and at least one `subject` block are required. Changing `role_ref` replaces the RoleBinding.

For existing SDKv2-managed bindings, see the [Plugin Framework upgrade guide](../guides/plugin-framework-upgrade-guide.md#resource-kubernetes_role_binding_v1) before upgrading.

A `User` or `Group` subject with `api_group = ""` shows a one-time in-place
update after upgrading, displayed as `- api_group = "rbac.authorization.k8s.io" -> null`.
SDKv2 stored the API server's default instead of the configured `""`. Only Terraform
state changes; the binding is not modified or replaced. To avoid the update, omit
`api_group` or set it to `rbac.authorization.k8s.io`.

## Example Usage

```terraform
resource "kubernetes_role_binding_v1" "example" {
  metadata {
    name      = "terraform-example"
    namespace = "default"
  }
  role_ref {
    api_group = "rbac.authorization.k8s.io"
    kind      = "Role"
    name      = "admin"
  }
  subject {
    kind      = "User"
    name      = "admin"
    api_group = "rbac.authorization.k8s.io"
  }
  subject {
    kind      = "ServiceAccount"
    name      = "default"
    namespace = "kube-system"
  }
  subject {
    kind      = "Group"
    name      = "system:masters"
    api_group = "rbac.authorization.k8s.io"
  }
}
```

## Import

RoleBinding can be imported using a non-empty namespace and name in the form `namespace/name`, for example:

```
$ terraform import kubernetes_role_binding_v1.example default/terraform-name
```

Identity import requires Terraform 1.12 or later. Use `api_version = "rbac.authorization.k8s.io/v1"`, `kind = "RoleBinding"`, and the binding's `name`; an omitted `namespace` defaults to `default`.

For a binding created with `generate_name`, configure the original prefix and omit `name` after import to avoid replacement.
